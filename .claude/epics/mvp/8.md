# Citation + confidence output contract

## Description

Define the shared structured-output contract both tabs consume: how the model
returns supporting citations (`DocName §X · p.N`) and a confidence value, and the
prompt strategy that elicits *honest* citations without fabrication. Decide and
document what the confidence value actually represents.

## Acceptance Criteria

- [x] A structured-output schema (e.g. JSON schema) for `{ value, citations[],
      confidence }` usable by both Assistant and Review.
- [x] Prompt strategy that elicits citations grounded in the provided documents,
      with a tested guard against fabricated citations.
- [x] A documented, defensible definition of what `confidence` means.
- [x] Verified against a sample doc set: citations point at real passages.

## Notes

- Resolves PRD open questions #2 (reliable elicitation) and #3 (what confidence means).
- This is the riskiest reliability surface in the MVP — full workflow gates on;
  consider Opus for authoring/testing the contract even though cells run Sonnet.
- Display-level only: pills render; click-to-source-PDF highlight is out of scope.

## Decisions
_Spec reviewed 2026-06-10 via /pm:spec-review. Verdict: approve._

Questions-phase decisions (locked with the user before authoring; binding):

- **[d1] Citation guard = verbatim quote anchor.** Every citation carries a short
  exact quote from the source; the anti-fabrication guard is that the quote must be
  findable in the stored document text (normalized-whitespace substring match) or it
  is flagged. Works uniformly for PDF and DOCX.
- **[d2] Keep page markers in extraction.** `src/lib/extract.ts` preserves
  pdf-parse's `-- N of M --` page-separator lines in stored `extractedText` (strip
  only for the internal empty-PDF guard), so `p.N` is verifiable instead of guessed.
- **[d3] Pill format.** PDFs cite `DocName §X · p.N` (page verified); DOCX cites
  `DocName §X`. Section included when located; verbatim quote always carried.
- **[d4] Confidence = "document support," 0–1, self-rated, auto-downgraded** to the
  low band if any citation fails the quote-check. Documented as "how well the
  documents support this answer," NOT "probability the answer is correct."
- **[d5] One schema, two emission modes.** Shared `{ value, citations[], confidence }`;
  Review forces structured JSON via Anthropic tool-use, Assistant streams prose then
  emits a delimited structured footer. Both single-shot.

Spec-review decisions:

- **[assumption] Module layout** — Confirmed: `contract.ts` (types + emission
  helpers) + `citation.ts` (pure verify + confidence fns).
- **[assumption] Define the shape with Zod** — Confirmed: Zod for runtime validation
  + generated JSON Schema for tool-use, not bare TS types.
- **[decision] Failed-quote action** — A: keep-but-flag (`verified:false`) and let it
  drive the confidence downgrade (not reject outright).
- **[assumption] Page derivation** — Confirmed: scan back to nearest `-- N of M --`
  marker for PDFs; undefined for DOCX and pre-existing (markerless) docs.
- **[decision] Confidence downgrade** — A: cap the **whole answer** at **0.3** on any
  citation-verification failure.
- **[decision] Structured-output mechanism** — A: forced tool-use for Review
  (guaranteed JSON) + streamed delimited footer for Assistant; both single-shot.
- **[risk] extract.ts change** — Acknowledged: keeping markers affects the empty-PDF
  guard (run it on a marker-stripped copy) and only helps re-uploaded docs
  (back-compat — page stays optional for pre-existing docs).
- **[risk] Streamed-footer parser** — Acknowledged: tolerate partial/malformed JSON
  mid-stream, parse only once the delimiter closes; the prompt must explain the
  page-marker chrome so it isn't mis-cited.
- **[risk] Prompt-caching interaction** — Acknowledged: placement of the
  anti-fabrication + structured-output prompt additions relative to the cached
  document prefix determines the #11 cache hit rate.
- **[risk] Strict substring verification** — Acknowledged: false-negatives on lightly
  paraphrased quotes are an accepted tradeoff (stricter/honest over looser).

Implementation-phase findings (recorded during subagent-driven execution; reviewed_sha 595e4d4):

- **[impl] Page markers are TRAILING separators — `derivePage` scans FORWARD.**
  Empirically, pdf-parse emits `-- N of M --` *after* each page's content
  (real output: `body1\n\n-- 1 of 2 --\n\nbody2\n\n-- 2 of 2 --`), not before it.
  The plan's literal `derivePage` scanned *backward* to the nearest preceding
  marker; that would mis-assign pages. Corrected to scan forward to the first
  marker after the quote (the marker that closes the quote's page). This honors
  decision n4's goal (a correct, verifiable page) and was explicitly authorized
  by the plan's Task 9 note ("adjust derivation to match observed output"). Proven
  on real extracted bytes by the Task 9 integration test (`page === 2`).
- **[impl] `section` is passed through UNVERIFIED.** The anti-fabrication guard
  anchors on the verbatim `quote` only (decision d1). A model-supplied `§X`
  section label is rendered on the pill (d3) without a check, so a fabricated
  section can surface. Accepted MVP limitation. NOTE for #9/#11: the UI must not
  imply the section is verified the way the quote/page are.
- **[impl] Pre-existing repo conditions, NOT introduced by #8:** (a) `tsc --noEmit`
  requires `prisma generate` first (the worktree's Prisma client is gitignored);
  with it generated, typecheck is clean. (b) `pnpm lint` fails on
  `design_handoff_legal_wrapper/*.jsx` mockups (49 errors) — unrelated to #8; all
  eight files this task touched are eslint-clean. That dir likely belongs in
  `.eslintignore` (out of #8 scope).
