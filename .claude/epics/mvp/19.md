# README + demo corpora

## Description

Write the setup README and prepare 2–3 curated demo corpora for the side-by-side
comparison demos. Pre-test the wrapper system prompt and a set of Assistant/
Review prompts against each corpus so the demo doesn't surface the same
hallucination we critique competitors for.

## Acceptance Criteria

- [ ] README: prerequisites (Node 20+, `ANTHROPIC_API_KEY`), install, `npm run dev`, usage.
- [ ] 2–3 curated demo corpora assembled, each under the token ceiling.
- [ ] A tested set of Assistant + Review prompts per corpus that demo reliably.
- [ ] Notes on 2–3 specific side-by-side comparisons to run vs. Harvey/Legora.

## Notes

- Resolves PRD open question #5 (which corpora) and finishes #4 (prompt tuning).
- Demo-hallucination mitigation: curate + pre-test rather than improvise live.
- Questions gate on: confirm corpora choices with the user before assembling.

## Decisions
_Spec reviewed 2026-06-15 via /pm:spec-review. Verdict: approve._

- **[decision] Which demo corpora to ship** — All three: a Vendor MSA set (for
  the Review grid), an NDA pair (for the Assistant compare flow), and one longer
  single agreement (for Assistant deep single-doc Q&A + the token meter).
- **[decision] Document sourcing** — Real public filings from **SEC EDGAR** to
  start (public record, freely redistributable), backfilling with synthetic
  contracts where a clean example is needed.
- **[decision] Repo footprint** — Keep **all** demo documents **out of git**
  entirely, and do **not** ship a manifest. The corpora are local-only; add
  `demo-corpora/` to `.gitignore`. (Overrides the spec's commit recommendation.)
- **[decision] README package manager** — Document **pnpm** (`pnpm install` →
  `pnpm db:migrate` → `pnpm dev`). Do **not** explain pnpm-vs-npm in the README;
  just use pnpm.
- **[decision] Home for tested prompts + notes** — A **separate demo guide**
  (`demo-corpora/README.md` or `docs/demo-script.md`), not the main README.
- **[assumption] README section order** — Confirmed: what-it-is → prerequisites
  → install → DB setup → run → usage walkthrough → known limits. Plus positioning
  copy (see Additional): a local, **Bring Your Own Model (BYOM)** alternative to
  expensive, heavily-marketed legal wrappers; built by a lawyer; no celebrity
  endorsements; a work in progress with more features coming.
- **[risk] Pre-testing burns API credits** — Override: the **user runs the
  prompt testing manually** to control token usage. Claude's deliverable is a
  **testing framework**, not test runs: a `.md` file with a table (prompt,
  expected outcome, corpus, tab, notes) the user can work through.
- **[risk] Comparison framing** — Override: **no side-by-side vs. Harvey/Legora
  right now.** It is sufficient to position the tool as a self-hosted,
  transparent, **BYOM** version of those products. Drop the comparison-notes
  deliverable from this task's scope.

> **Additional —**
> - Sourcing: start with real SEC EDGAR contracts, backfill with synthetic.
> - README positioning: a local, BYOM alternative to expensive, heavily-marketed
>   legal wrappers; created by a lawyer; no celebrity endorsements; a work in
>   progress with more features coming. Do not justify pnpm over npm.
> - **Sequencing: the README is the top priority.** The demo guide, the corpora
>   themselves, and the testing-framework `.md` come afterwards.
