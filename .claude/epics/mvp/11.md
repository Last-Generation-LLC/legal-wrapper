# System-prompt panel (visible/editable)

## Description

The transparency feature: a collapsible "Show/Hide prompt" panel exposing the
actual editable system prompt. Char + token estimate, Reset and Copy, and the
`{{DOCUMENTS}}` footer note. Edits flow into the Assistant API call.

## Acceptance Criteria

- [ ] "Show/Hide prompt" toggle reveals an editable textarea (hidden by default).
- [ ] Live char count + token estimate as the user types.
- [ ] Reset restores the default prompt; Copy copies it.
- [ ] Footer note explains `{{DOCUMENTS}}` is replaced server-side; nothing hidden.
- [ ] Edited prompt is what actually gets sent on the next message.

## Decisions

- Autonomous fast path approved by user (2026-06-12, "go for 11"): the handoff
  panel (`assistant.jsx` lines 188-225) is the visual spec; decisions below are
  mine, recorded for the ship review.
- Panel renders between the context strip and the thread (mockup position);
  template state lives in assistant-chat, in-memory. "New session" clears the
  thread but KEEPS the edited template (it's a setting, not a message); reload
  resets to the shipped default.
- Blank/whitespace-only template falls back to the default at send (an empty
  system prompt can't be sent); the panel says so when blank.
- If the edited template drops `{{DOCUMENTS}}`, an amber warning appears
  (via templateHasDocumentsToken) explaining the server appends the documents
  block at the end instead — matching composeSystemPrompt's actual behavior.
- Char count exact; token estimate via the existing estimateTokens (~4 chars).
- Copy copies the current template (with "Copied" feedback, same pattern as
  chat-message); Reset restores DEFAULT_SYSTEM_PROMPT immediately, no confirm.
