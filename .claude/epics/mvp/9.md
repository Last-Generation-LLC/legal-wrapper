# Assistant chat API (streaming, Opus)

## Description

Build the Assistant API route: accept `{ docs, sysPrompt, messages }`, compose
the wrapper with selected document text, call Claude (Opus) with streaming via
the Vercel AI SDK, and stream back the assistant message plus citations and
confidence per the contract.

## Acceptance Criteria

- [x] Route accepts selected doc IDs, the (possibly user-edited) system prompt, and message history.
- [x] `{{DOCUMENTS}}` replaced server-side with selected-doc text; nothing hidden.
- [x] Streams Opus output token-by-token to the client.
- [x] Returns citations + confidence per the 007 contract.
- [x] Single-shot call — no agent loop.

## Notes

- Uses the wrapper (006) and contract (007). Verify AI SDK streaming patterns
  against live docs.
- Shares the Anthropic lib with the Review API (011) — conflicts_with: 011.

## Decisions
_Spec reviewed 2026-06-11 via /pm:spec-review. Verdict: approve._

- **[decision] Streaming transport** — A: Vercel AI SDK (`streamText` + UI
  message stream, `useChat`-native). No hand-rolled SSE.
- **[assumption] anthropic.ts seam owns both client paths** — Confirmed: the raw
  `getAnthropic()` AND the AI SDK provider (`createAnthropic`); no route imports
  `@ai-sdk/anthropic` directly. Optional `apiKey` arg leaves room for future
  BYO-key (#20).
- **[decision] Citations delivery** — A: stream prose as-is; when the stream
  finishes server-side, run `parseAssistantFooter` + `verifyAnswer` and attach
  the `VerifiedAnswer` as a structured data part on the same stream.
- **[context] Cross-task footer contract** — Acknowledged: the raw footer text
  flows through the visible stream; hiding it during render is #10's job via
  `parseAssistantFooter`.
- **[decision] Transparency boundary** — A: the citation strategy block is
  appended after the editable template and shown verbatim but NOT editable in
  the prompt panel. Final prompt = editable template (docs filled) +
  `assistantPromptStrategy()`, fixed order, nothing else.
- **[decision] Chat persistence scope** — A: #9 stays stateless — client sends
  full message history each call; route never writes. Follow-up persistence
  task filed as #21.
- **[assumption] Request shape** — Confirmed: `POST /api/assistant/chat`,
  zod-validated body `{ docIds: string[], systemPromptTemplate: string,
  messages: UIMessage[] }`; server fetches full doc text by id from Prisma
  (client never sends text); error shape `{ error }` with status codes matching
  `/api/upload`; `runtime = "nodejs"`.
- **[assumption] Model settings** — Confirmed: `modelFor("assistant")` =
  claude-opus-4-8; single-shot `streamText`, NO tools, no multi-step loop;
  `maxOutputTokens` ~4096; temperature at SDK default.
- **[decision] Empty docIds** — A: allowed (chat without documents);
  `composeSystemPrompt` with empty docs, no 400.
- **[risk] Footer fragility** — Acknowledged: on missing/malformed footer the
  route skips the data part and returns the prose unchanged (citations +
  confidence absent, never an error).
- **[risk] Context ceiling pre-#15** — Acknowledged: a mid-stream Anthropic
  context-limit error surfaces through the stream's `onError` as a legible
  message, not a silent hang or stack trace.
- **[risk] New deps (`ai` + `@ai-sdk/anthropic`)** — Acknowledged, AMENDED by
  reviewer note: use the most up-to-date AI SDK version (latest stable at
  implementation time) rather than hard-pinning v5. Root `pnpm install` after
  the merge remains required or main won't build.

> Additional: Transparency must not become obtuse. Where full prompt/citation
> detail gets heavy, prefer progressive disclosure — detail collapsed by
> default with a click-to-expand, like GenAI thinking traces or Claude Code's
> ctrl+o. Guidance applies to how #10/#11 surface the composed prompt and
> citation metadata; #9 should expose the data in a way that lets the UI
> de-emphasize it.

- **[plan] Deep message validation via `validateUIMessages`** — Accepted drift:
  the AI SDK's own validator (with `TypeValidationError` → 400) replaces a
  hand-written zod UIMessage schema; zod still validates the outer body.
- **[plan] Unknown docIds → 404 listing the missing ids** — Accepted drift:
  a case the spec didn't address; follows the upload route's `{ error }` +
  status-code convention.
- **[plan] Documents re-ordered to selection order** — Accepted drift:
  `findMany` returns arbitrary order; the route restores the request's
  `docIds` order before prompt composition so the rendered doc blocks match
  the user's selection.
