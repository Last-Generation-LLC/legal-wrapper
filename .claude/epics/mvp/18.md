# Empty states + error toasts

## Description

Add the polish layer: empty states (no documents uploaded, no docs selected, no
columns defined, empty grid) and error toasts for upload failures, API errors,
and parse errors across both tabs.

## Acceptance Criteria

- [ ] Empty states for: no docs uploaded, none selected, no Review columns, empty grid.
- [ ] Error toasts for upload, parse, and API failures with actionable messages.
- [ ] Empty/error styling matches the design language (terminal-adjacent, amber/red tones).

## Decisions

Recorded 2026-06-14 at issue-start (the code already had basic versions of both
features — dim one-liner empty states and inline error text — so these decisions
scope the delta):

- **Toast library: `sonner`** — shadcn-blessed, minimal, fits the dark/mono
  aesthetic. Mounted once in the root layout, themed to match.
- **Toast scope: upload/parse only.** Upload + PDF-parse failures (both surface
  from `/api/upload`) fire a toast. Chat-API errors stay inline (they already
  have a Retry affordance); Review cell errors stay inline (a 50-cell grid can't
  be represented as toasts). **This deliberately narrows acceptance criterion #2**
  ("upload, parse, and API failures") — API failures keep their existing inline
  homes by design, not by omission.
- **Empty states: elevated treatment.** Each of the four states (no docs
  uploaded, no docs selected — Assistant & Review, no Review columns) gets a
  faint icon + short heading + actionable hint/CTA, built on one shared
  `EmptyState` primitive for consistency. "Empty grid" == "no docs selected" in
  Review (rows derive from selected docs), so it reuses that state.
- **"No columns" is reachable** — `deleteColumn` has no floor, so a user can
  delete all 6 starter columns; that empty state is in scope.
