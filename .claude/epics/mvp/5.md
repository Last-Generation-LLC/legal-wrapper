# Upload + text-extraction API

## Description

Build `/api/upload`: accept PDF and DOCX files, extract plain text (`pdf-parse`
for PDF, `mammoth` for DOCX), compute a token count, and persist a `Document`
row to SQLite.

## Acceptance Criteria

- [ ] `POST /api/upload` accepts PDF and DOCX; rejects other types with a clear error.
- [ ] PDF text via `pdf-parse`, DOCX text via `mammoth`.
- [ ] Token count computed and stored alongside the extracted text.
- [ ] Document persisted to SQLite; endpoint returns the saved document metadata.
- [ ] Parse failures (scanned/complex PDFs) return a clear, debuggable error,
      not a silent empty document.

## Notes

- PDF parse quality is a known risk (scans/tables/heavy layout). Surface the
  limit rather than failing silently — keep extraction behind a clean interface
  so a hosted parser could be swapped in later.
- Use the Anthropic token-counting approach for `tokenCount` so the context
  meter is accurate (verify the current method when wiring 006).
