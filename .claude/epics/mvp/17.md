# Cost + cache surfacing

## Description

Surface cost and cache transparency from the handoff: per-message cost estimate
and cache-hit % in the Assistant context strip, and per-run cost estimate +
cache % in the Review header. Derive numbers from the API usage fields (input,
output, cached tokens) and current pricing.

## Acceptance Criteria

- [x] Assistant shows `est. $X / msg` and `cache hit · N%` per the handoff.
- [x] Review shows a per-run cost estimate and `cache · N%`.
- [x] Figures derived from real usage fields, not hardcoded.
- [x] Pricing constants live in one config spot, easy to update.

## Notes

- Reinforces the "overpriced" thesis — showing the real (tiny) cost is the point.
- Verify current model pricing + usage field names against live Anthropic docs.
- Touches both tab UIs → conflicts_with: 009, 012.

## Decisions

- **[plan] Enable Assistant prompt caching as part of #17** — User-confirmed scope:
  add one `cacheControl: ephemeral` breakpoint on the Assistant's document-bearing
  system prompt so multi-turn chats get real cache hits (turn 2+ pays ~10% on doc
  tokens). Without it the strip's "cache hit · N%" would always read 0%. The chat
  route comment already pre-committed caching to #17. Review-cell caching already
  exists and is untouched.
- **[plan] One pricing module, keyed by model id** — `src/lib/pricing.ts` holds the
  canonical `TokenUsage` shape, the verified per-model rates ($5/$25 Opus, $3/$15
  Sonnet per MTok), the cache multipliers (write 1.25× / read 0.1×, 5-min TTL), and
  the cost/cache/format helpers. Pure and client-safe (no SDK import). Server pages
  already call `modelFor(role)`, so they pass a `modelId` prop to the client screens
  — no client-side SDK import, no duplication of the model registry.
- **[plan] Normalize usage at each route** — the raw SDK reports `input_tokens` as
  *uncached only*, while `@ai-sdk/anthropic` reports `inputTokens` as the *total
  incl. cache* (cache-write only in `providerMetadata.anthropic.cacheCreationInputTokens`).
  Both routes map to the one canonical `TokenUsage` where the fields are unambiguous,
  so the pricing math has a single contract.
- **[plan] Per-run cost = sum of all `done` cells** currently in the grid (the
  session's real spend); running/idle/error cells contribute nothing. Figures hide
  until at least one cell has run.
- **[plan] Cost + cache pills placement** — Review: in the StatusBar header. Assistant:
  on the right of the CONTEXT strip (per handoff), reflecting the most recent
  completed answer's real usage (`est. $X / msg`).
- **[plan] No metadata migration** — `AssistantMetadata` moves to `usage?: TokenUsage`;
  pre-#17 persisted messages lack `usage` and simply show no cost line (local dev
  data, no migration warranted).
