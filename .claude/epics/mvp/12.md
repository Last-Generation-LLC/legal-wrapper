# Review cell API + prompt caching

## Description

Build the per-cell Review API: accept `{ doc, columnPrompt }`, compose the
wrapper with the document text, call Claude (Sonnet), and return
`{ value, confidence, citation }` per the contract. **Enable Anthropic prompt
caching on the document text** so repeated cells against the same document pay a
fraction of input cost — this is load-bearing, not polish.

## Acceptance Criteria

- [ ] `POST` per-cell route accepts a document + a column prompt.
- [ ] Document text marked as a cache breakpoint; subsequent cells against the
      same doc register cache hits (verified via response usage fields).
- [ ] Returns value + confidence + citation per the 007 contract.
- [ ] Uses Sonnet; single-shot call.
- [ ] Errors return a debuggable message (e.g. "parse error: §7 contains table").

## Decisions

- Spec/spec-review/plan phases skipped by user decision (2026-06-12, #10-style
  fast path): the #8 contract (forced tool-use via `buildReviewTool()` /
  `REVIEW_TOOL_NAME`, decision d5) plus these recorded decisions are the spec.
- Client path: RAW Anthropic SDK (`getAnthropic()` through the anthropic.ts
  seam), non-streaming single-shot `messages.create` with
  `tool_choice: {type: "tool", name: submit_answer, disable_parallel_tool_use}`.
  AI SDK path is for streaming surfaces only (per model-seam decision).
- Request: `POST { docId, prompt, systemPromptTemplate? }` — ONE cell per call.
  Doc fetched by id server-side (same pattern as the assistant route).
- Response: `{ answer: VerifiedAnswer, usage: { inputTokens, outputTokens,
  cacheReadInputTokens, cacheCreationInputTokens } }` — usage surfaced now so
  #17 (cost + cache UI) is a pure frontend task.
- Caching: single system text block = review template (doc text filled) +
  reviewPromptStrategy, with `cache_control: {type: "ephemeral"}` (5-min TTL —
  grid runs are bursty; 1h TTL doubles write cost for no benefit). The varying
  column prompt rides the user message AFTER the breakpoint. Tools render
  before system and are deterministic, so the breakpoint covers them too.
- Sonnet 4.6 minimum cacheable prefix is 2048 tokens: docs smaller than that
  silently don't cache (full price, no error). Accepted — real legal docs
  clear it; surfacing the condition in UI is #17's scope.
- Verification: same server-side `verifyAnswer` + confidence-cap path as the
  Assistant (#9) — one contract, both tabs.
- NOTE FOR #13 (grid runner): concurrent identical-prefix requests all MISS
  the cache (an entry is readable only after the first response begins).
  The runner must fire ONE cell per document first, await it, then fan out
  the remaining cells for that document.
