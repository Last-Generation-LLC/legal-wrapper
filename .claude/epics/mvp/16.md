# Token-ceiling guardrails

## Description

Enforce the no-RAG context ceiling everywhere it matters: a warning as the
combined selected-document tokens approach ~180k, and a clear, blocking error
(not a silent bad call) when a request would exceed the window — in both the
Assistant and the Review API paths and their UIs.

## Acceptance Criteria

- [ ] Combined selected-doc token total is visible and warns as it nears ~180k.
- [ ] Assistant blocks the call past the ceiling with a clear message.
- [ ] Review blocks affected cells past the ceiling with a clear per-cell error.
- [ ] No silent truncation or silently failing calls.

## Decisions

- Autonomous fast path approved by user (2026-06-12, "go for ... 16").
- ONE shared constant: `CONTEXT_CEILING = 180_000` and `ceilingState(tokens)`
  ("ok" / "warn" at >=80% / "over" past 100%) live in a new client-safe
  `src/lib/context-ceiling.ts`; docs-context, sidebar, assistant UI, and both
  API routes import it — the number can never drift between surfaces.
- Warning surface: the sidebar's existing token meter + count turn amber at
  "warn" and red at "over" (the meter already shows X / 180k).
- Assistant, client side: when the selection is "over", Send is blocked with
  an inline red message naming the overage — no API call is made.
- Assistant, server side (defense in depth): the chat route sums the selected
  docs' stored tokenCounts and returns 413 with a clear message BEFORE calling
  the model. The existing reactive mapping (Anthropic "prompt is too long" →
  legible message) stays as the catch-all.
- Review, server side: the cell route 413s when the document's stored
  tokenCount exceeds the ceiling, before the model call. The grid already
  renders per-cell route errors, and the #13 warm-skip prevents burning the
  doc's remaining cells — an oversized doc costs ONE cheap HTTP round-trip.
- Stored tokenCounts are the guard's basis (estimated ones included): the
  guard is approximate by design; the reactive server mapping remains the
  authoritative backstop. No truncation anywhere — over means blocked, never
  silently trimmed.

## Plan

1. `src/lib/context-ceiling.ts` + tests: constant, ceilingState, overage
   message helpers. Re-point docs-context's local CONTEXT_CEILING at it.
2. Sidebar: color meter/count by state (amber/red) + warn label.
3. Assistant: assistant-chat computes the state from useDocs; Composer takes a
   `blocked` message prop — Send disabled + red inline note when set.
4. Chat route: pre-call 413 guard summing doc tokenCounts; test.
5. Cell route: pre-call 413 guard on doc.tokenCount; test.

## Notes

- This is the mitigation for the PRD's "Context ceiling" risk — the no-RAG
  approach has a hard wall, not graceful degradation.
- Cross-cutting: touches both API routes and both UIs → conflicts_with several.
