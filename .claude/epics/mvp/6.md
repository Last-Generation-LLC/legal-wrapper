# Document sidebar UI

## Description

Build the 280px document sidebar from the handoff: workspace header with an
Upload button, the IN-CONTEXT section with a context meter, and a scrollable
document list with per-doc checkboxes and token metadata. Owns the
`selectedDocs` multi-select state shared with the Assistant.

## Acceptance Criteria

- [ ] Workspace header (serif title, mono doc/token sub-line) + ghost Upload button.
- [ ] IN-CONTEXT label with count + token usage and a 3px amber context meter bar.
- [ ] Scrollable doc list; each row shows checkbox + name + mono metadata
      (`MSA · 42p · 31.4k tok`); selected rows get panelHi background.
- [ ] Clicking a row toggles selection and updates the meter + count live.
- [ ] Upload button wires to `/api/upload` and refreshes the list.

## Notes

- Matches handoff "Document Sidebar (280px)" spec; visual fidelity → review gate on.
- `selectedDocs: string[]` is the shared state consumed by the Assistant (008/009).

## Decisions
_Spec reviewed 2026-06-10 via /pm:spec-review. Verdict: approve._

- **[decision] Where the sidebar mounts + where `selectedDocs` lives** — A:
  build a `DocSidebar` client component + a `DocsProvider` React context
  (`documents`, `selectedDocs`, `toggle`) mounted at the **Assistant route** via
  an `(workspace)/assistant/layout.tsx` wrapping the sidebar + page. The future
  Assistant chat (#9) reads the same selection through a `useDocs()` hook. The
  sidebar is NOT forced onto Review/Documents — Review has its own layout.
- **[decision] How the document list is loaded** — A: a Server Component calls
  `prisma.document.findMany` (metadata-only select, newest first) using the
  existing `@/lib/prisma` singleton and seeds the `DocsProvider`; after a
  successful upload the client calls `router.refresh()` to re-run the server
  fetch. No new `GET /api/documents` route.
- **[decision] Metadata-row content (schema gap)** — A: render
  `{FORMAT} · {tokens}k tok` where FORMAT is PDF/DOCX derived from `mimeType`;
  prefix the token count with `~` when `tokenCountEstimated` is true; row label
  is `title ?? filename`. Drop the handoff's fictional page count and MSA/DPA
  doc-type taxonomy (no schema change — extending #3/#5 was rejected as scope
  creep into shipped tasks).
- **[assumption] Workspace header copy** — Confirmed: no matter/workspace
  entity in the MVP, so the serif title is a static product label (e.g.
  "Workspace") and the mono sub-line is computed live as `{N} documents ·
  {total} tokens` over ALL uploaded docs.
- **[assumption] Context meter math** — Confirmed: meter = `selectedTokens /
  180000`, clamped at 100%, amber 3px bar, label `{k}k / 180k`, `In Context ·
  {count}`. Warning/hard-error guardrails near the ceiling are task #16, out of
  scope here — the meter only fills.
- **[assumption] Selection persistence** — Confirmed: `selectedDocs` is
  in-memory React state only; resets on reload, no DB/localStorage persistence.
- **[assumption] Upload UX** — Confirmed: a hidden `<input type="file"
  accept=".pdf,.docx">` triggered by the ghost Btn; one file per POST (the route
  takes a single `file`); multi-file upload is deferred.
- **[risk] Upload error handling** — Acknowledged: surface the route's
  400/413/422 errors (unsupported type, >25 MB, parse failure) as a minimal
  inline message near the Upload button, not a silent no-op. The full toast
  system is task #17.
- **[risk] Empty state** — Acknowledged: with zero documents the list, meter,
  and counts must render sensibly (e.g. "No documents yet"); a minimal
  placeholder now, polished empty states land with #17.
- **[context] Primitives & tokens to reuse** — Reuse `Btn`/`Pill`/`Icon`, the
  semantic icon names, the dark design tokens, and the per-file jsdom test
  setup. No new primitives; do not restyle the shell.
