# Review grid UI

## Description

Build the Review grid from the handoff: sticky document column + sticky prompt-
column headers (with editable prompts), rows per document, the four cell states
(idle / running / error / done), the status bar with the multi-segment progress
bar, and "Run all" with a ~5-parallel concurrency cap.

## Acceptance Criteria

- [x] Grid: sticky-left Document column + sticky prompt-column headers; add column / add documents.
- [x] Columns are user-defined: rename + edit prompt + delete.
- [x] Cell states render per handoff: idle (—), running (shimmer), error (red + message), done (value + confidence dot + citation).
- [x] "Run all" runs every cell with concurrency capped at ~5 parallel requests.
- [x] Cells complete independently; status bar progress (done/running/error) updates live.

## Decisions

- Spec/spec-review/plan phases skipped by user decision (2026-06-12, #10-style
  fast path): the Claude Design handoff (`components/review.jsx`) is the visual
  spec; these decisions + the #12 cell API contract are the rest.
- Scope: grid + runner only. Inspector drawer is #14, CSV export is #15 (the
  Notes' "013/014" refer to those). The top-bar CSV button and the bottom
  inspector drawer are NOT built in #13.
- Column definitions (title + prompt) persist to localStorage — survives reload,
  no schema change. SQLite persistence is an explicit follow-up task ("local
  for now. SQLite later." — user). Cell results are in-memory only.
- Rows = the shared sidebar `selectedDocs` selection (same model as the
  Assistant). The handoff's "Add documents" button points the user at the
  sidebar rather than opening a separate picker.
- First visit (empty localStorage) seeds the handoff's 6 NDA starter columns,
  all renameable/editable/deletable.
- "Run all" runs idle + error cells, PLUS done cells whose column prompt
  changed since they ran (each done cell remembers the prompt it ran with).
  Done cells with an unchanged prompt are never re-billed. A separate
  "re-run all" action is a future follow-up — out of scope (user).
- Runner honors the #12 cache-warming note: fire ONE cell per document first,
  await it (cache write), then fan out that document's remaining cells.
  Global concurrency cap ~5 across documents.
- Top bar shows the model pill (via `modelDisplayLabel(modelFor("review"))`);
  the cache-rate pill from the mockup is #17's scope (cost + cache surfacing).

## Notes

- Largest Review task; matches handoff "Review Page" spec. Visual fidelity → review gate on.
- The ~5 concurrency cap protects rate limits and keeps caching effective.
- Inspector drawer and CSV export are split into 013 and 014 → conflicts_with both.
