# Design system port: tokens, primitives, layout shell

## Description

Port the `design_handoff_legal_wrapper/` design language into the app: OKLCH
color tokens into the Tailwind theme, the three fonts (Inter Tight, Instrument
Serif, JetBrains Mono), small-radius/terminal-adjacent defaults, and the shared
primitives (`Pill`, `Btn`, `Icon`) plus the persistent `Rail` and `TopBar`
layout shell. Establish the App Router routes for Assistant, Review, and
Documents.

## Acceptance Criteria

- [ ] Tailwind theme encodes the OKLCH tokens (bg, panel, panelHi, border, text,
      muted, dim, amber, green, red, blue, etc.) from the handoff README.
- [ ] Fonts loaded (self-hosted or Google Fonts) and applied per the type scale.
- [ ] `Pill` (default/active/ctx/ok/warn), `Btn` (primary/default/ghost, sm/md),
      and `Icon` primitives match the handoff spec.
- [ ] `Rail` (56px) + `TopBar` (44px) layout shell wraps route content.
- [ ] Routes exist for Assistant, Review, Documents; small radii (3–4px) preserved.

## Notes

- Visual fidelity matters and the handoff is dense — spec + review gates on.
- Do NOT port `design-canvas.jsx` (dev tooling). Make it responsive below 1440px
  (sidebar → drawer, inspector → stacked) per the handoff.
- The handoff HTML uses inline styles + React UMD; do not carry those over.

## Decisions
_Spec reviewed 2026-06-10 via /pm:spec-review. Verdict: approve._

- **[decision] Token architecture** — Do both: remap shadcn's semantic
  variables onto the handoff palette AND expose the handoff's named tokens as
  Tailwind v4 `@theme` colors (`--color-bg`, `--color-panel`, `--color-amber`,
  …). Per the user's override, **keep shadcn's dual light/`.dark` theme
  structure rather than collapsing to dark-only**: populate the warm-gray
  handoff palette into the dark theme and pin the app to dark (`<html>` gets the
  `dark` class) so light mode remains a latent future toggle, not a rebuild.
  The approved OKLCH palette values are not changed — surface any color change
  to the user for sign-off.
- **[assumption] Fonts** — Confirmed: load Inter Tight, Instrument Serif
  (400 + italic), and JetBrains Mono via `next/font/google` in `layout.tsx`,
  replacing Geist; CSS variables feed the `@theme` font tokens.
- **[risk] Radius creep** — Acknowledged: clamp `--radius` to ~4px in
  `globals.css`, keep bespoke primitives at 3px, and run a visual audit so
  nothing exceeds 3–4px.
- **[decision] Route structure** — A: a `src/app/(workspace)/` route group
  holds `assistant/`, `review/`, `documents/` page stubs; the group
  `layout.tsx` renders the persistent Rail + shell; root `src/app/page.tsx`
  redirects to `/assistant`; the Rail highlights the active section via
  `usePathname()` (client component).
- **[assumption] TopBar composition** — Confirmed: `TopBar` is a shared
  component each page renders (passing its own breadcrumb crumbs + a right
  cluster slot); the Rail (identical everywhere) lives in the group layout.
- **[decision] Primitives** — A: build dedicated CVA `Pill` / `Btn` / `Icon`
  primitives under `src/components/ui/` (matching the existing `button.tsx`
  pattern + `cn()`); keep the shadcn `button.tsx` available for generic needs.
- **[assumption] Icons** — Confirmed: map the handoff icons to `lucide-react`
  equivalents rather than porting raw SVG path data; verify each name resolves
  against the installed `lucide-react` (^1.17) and substitute the nearest match
  for any that drifted.
- **[assumption] Route content** — Confirmed: routes are placeholder stubs —
  each renders the `TopBar` + an empty "coming soon" main region. The real
  Assistant chat, Review grid, and Documents content are later tasks (#9, #12,
  #5).
- **[risk] Rethemeing the scaffold** — Acknowledged: forcing dark + remapping
  the semantic tokens changes how shadcn components render; verify the shadcn
  `Button` renders correctly (legible text, primary = light-bg/dark-text) under
  the new dark tokens before closing the task.
- **[assumption] Responsive scope** — Resolved (was PENDING): this task makes
  only the shell responsive (Rail persists, main column flexes). The
  sidebar-collapses-to-drawer behavior ships with #5 and the
  inspector-stacks behavior with #12 — responsive logic lands with the surface
  it applies to.
- **[plan] Component test infrastructure** — Accepted drift: add jsdom +
  `@testing-library/react`/`dom`/`jest-dom` devDeps and a `src/test/setup-dom.ts`
  setup file (wired into `vitest.config.ts`) as the prerequisite for TDD'ing the
  Pill/Btn/Icon/TopBar/Rail primitives; gated so the existing node-env tests are
  undisturbed.
- **[plan] Icon mapping module** — Accepted drift: a dedicated
  `src/components/icons.ts` semantic-name → lucide component map as a single
  swap point, rather than importing lucide directly inside the `Icon` primitive.
- **[plan] Rail wordmark** — Resolved: use "LLW" (Local Legal Wrapper) as the
  Rail wordmark. Fits the ~36px logo box at 10px mono; one-line change to "LW"
  if a shorter mark is preferred later.
