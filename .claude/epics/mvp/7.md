# Anthropic client + wrapper system prompt

## Description

Set up the Anthropic SDK client and the wrapper layer that is core to the thesis:
a tuned legal-workflow system prompt containing a literal `{{DOCUMENTS}}` token,
plus the server-side composition that replaces that token with the full text of
the selected documents on each call. Pin the model IDs after verifying them
against live Anthropic docs.

## Acceptance Criteria

- [ ] Anthropic SDK client configured from `ANTHROPIC_API_KEY`.
- [ ] Model IDs for Assistant (Opus) and Review (Sonnet) verified against live
      docs and pinned in one config location (the mock "4.5" labels are placeholders).
- [ ] A documented, tuned legal system prompt with a `{{DOCUMENTS}}` token.
- [ ] Server-side composer replaces `{{DOCUMENTS}}` with selected-doc text.
- [ ] Token counting available for context-meter accuracy.

## Notes

- Resolves PRD open questions #1 (model IDs) and partially #4 (system prompt).
- VERIFY model IDs and SDK surface against live Anthropic docs before coding —
  do not trust memory or the mock labels.
- Questions gate on: confirm the wrapper prompt's tone/scope with the user.

## Decisions
_Spec reviewed 2026-06-10 via /pm:spec-review. Verdict: approve._

- **[decision] Model IDs to pin** — Pin `claude-opus-4-8` (Assistant) and
  `claude-sonnet-4-6` (Review), verified against live Anthropic docs (resolves
  PRD open Q#1; the mock "4.5" labels are placeholders). **Design the model
  config to be modular**: a swappable registry/config object rather than
  hardcoded inline IDs, so a *later phase* can let users change models or bring
  their own API key/provider. The user-facing override feature itself is OUT OF
  SCOPE for this task — only the modular design that makes it cheap later is in
  scope.
- **[decision] Default system prompt** — Adopt the design mock's contract-review
  prompt (`DEFAULT_SYS_PROMPT` in `design_handoff_legal_wrapper/components/assistant.jsx`)
  verbatim as the shipped default. It is editable at runtime, so it only needs
  to be a strong starting point.
- **[decision] Multi-doc `{{DOCUMENTS}}` rendering** — Render each selected
  document as a delimited block: a header line `===== DOCUMENT: <name> =====`
  (name = `title` if present, else `filename`) followed by the full
  `extractedText`, blocks joined in selection order.
- **[decision] Missing-token behavior** — If a user-edited prompt omits the
  literal `{{DOCUMENTS}}` token, append the documents block at the end of the
  prompt AND surface a warning (do not silently drop the docs, do not reject the
  send).
- **[assumption] Module shape** — Model map lives in `src/lib/anthropic.ts`
  (alongside the existing `getAnthropic()` + `TOKEN_COUNT_MODEL`);
  `DEFAULT_SYSTEM_PROMPT` and the composer live in a new sibling
  `src/lib/wrapper.ts`. Confirmed.
- **[assumption] Composer signature** — `composeSystemPrompt` is a pure,
  server-side, unit-testable function: `(docs: Document[], template = DEFAULT) => string`.
  Confirmed.
- **[context] Scope boundary** — Deferred to later tasks: the Assistant chat
  API / streaming call, the editable system-prompt UI panel, the
  citation+confidence output contract, and Review-grid prompt caching. This task
  ships the server-side building blocks only.
- **[context] Token counting** — Already provided by `countTokens` in
  `src/lib/tokens.ts` (from #5); this task adds nothing new for the context
  meter beyond ensuring the composed prompt can be measured.
- **[risk] Editable prompt sent verbatim** — Acknowledged. The edited prompt is
  sent to Claude as-is (consistent with the "nothing is hidden" thesis); no
  prompt-injection hardening. Acceptable for a local single-user demo; revisit
  if it ever goes multi-tenant.

> Additional: Model IDs should be pinned for now but the config designed
> modularly so a later phase can let users change models / use their own APIs.

- **[plan] Helper functions beyond the composer** — Accepted drift: `wrapper.ts`
  also exports `renderDocuments` (d3's delimited-block rendering) and
  `templateHasDocumentsToken` (d4's missing-token detection); `anthropic.ts`
  exports `modelFor` (d1's registry accessor seam). d6 constrains only
  `composeSystemPrompt`'s signature/purity, not siblings.
- **[plan] Missing-token warning surfaced via predicate** — Accepted drift: the
  d4 warning is exposed through `templateHasDocumentsToken()` for callers to
  surface in the (future) UI, rather than `composeSystemPrompt` returning a
  warning — keeping the composer's return type `string` per d6 while still
  guaranteeing docs are never silently dropped.
- **[plan] TOKEN_COUNT_MODEL derived from registry** — Accepted drift:
  `TOKEN_COUNT_MODEL = MODELS.assistant` (single source of truth) instead of a
  separate literal. Runtime value unchanged (`claude-opus-4-8`), so `tokens.ts`
  is unaffected.
